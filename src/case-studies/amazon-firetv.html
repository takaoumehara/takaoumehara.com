The TV is the stage, the phone is the input テレビは舞台、スマホは入力

Each input does the job it is best at. The D-pad browses rails of products from across the room. Voice carries intent: press V or the mic and say “show me chocolate protein”, “add this to my cart” or “checkout”, and a local intent parser routes the command. When you need to type, point precisely or talk privately, the phone is already paired: it becomes a D-pad, joystick, trackpad, search box and hold-to-talk mic. The TV layout is built for ten feet — oversized focus rings, a dark, high-contrast screen. 入力ごとに、得意な仕事だけを任せた。部屋の向こうから商品の列を眺めるのは D-pad。意図を伝えるのは声。V キーかマイクを押して「チョコ味のプロテインを見せて」「カートに入れて」「購入」と言う。すると端末の中の意図解析が、命令を振り分ける。文字を打つ、細かく指す、小声で話す。そのときスマホはもうつながっていて、D-pad、ジョイスティック、トラックパッド、検索欄、押して話すマイクになる。テレビ側の画面は 3 メートル先から見る前提で、大きなフォーカス枠とコントラストの強い暗い画面にした。

One scan to pair, one state on both screens 読み取りは 1 回、状態は両方の画面で同じ

Pairing runs on snap-pair, my open-source pattern (now published as snap-pair-core): a QR code or a 6-character room code as the rendezvous, room membership checked on the server, a presence heartbeat, and automatic cleanup when someone leaves. The library has since grown to also support 6-digit PIN, experimental ultrasonic sound pairing, and transports beyond Firebase (PartyKit, WebRTC, BroadcastChannel). Once paired, the cart count, the current screen and the search context are mirrored to the phone in real time, so the remote always knows what the TV is showing. The whole prototype is plain HTML, CSS and JavaScript with Firebase and the Web Speech API — no bundler, no framework — so it runs from a folder or any static host. 接続には、自作して公開している snap-pair の型を使った。QR か 6 文字のルームコードを待ち合わせの目印にし、部屋への参加はサーバー側で確かめる。つながっているかを定期的に確認し、抜けた人は自動で片づける。つながった後は、カートの点数、いま出ている画面、検索の文脈がリアルタイムにスマホへ映る。だからリモコンは、テレビが何を見せているかを常に知っている。試作全体は素の HTML・CSS・JavaScript に Firebase と Web Speech API だけ。バンドラーもフレームワークもなく、フォルダーひとつ、どんな静的ホストでも動く。
