The Challenge 課題

Wireless plan pricing is inherently confusing. Customers adding multiple phone lines face compounding complexity: per-line costs shift based on plan tier, device selection, and discount combinations like AutoPay or BYOD. The existing purchase flow made it nearly impossible for customers to understand what they would actually pay each month — especially when configuring 2, 3, or 4 lines simultaneously. 携帯プランの料金は、そもそも分かりにくい。回線を何本も追加する人は、プランの段階、選ぶ端末、AutoPay や持ち込み端末（BYOD）といった割引の組み合わせによって、1回線あたりの金額がそのたびに変わるという複雑さに直面する。それまでの購入フローでは、特に2回線、3回線、4回線を同時に申し込む場合、毎月いくら払うことになるのかを把握するのがほぼ不可能だった。

The cart was a black box. Customers couldn't see a per-line breakdown, couldn't understand how discounts were applied, and often abandoned the flow out of confusion rather than cost. The core problem wasn't the price itself — it was the lack of price transparency at the moment of decision. カートの中身は、完全に見えなかった。回線ごとの内訳が確認できず、割引がどう効いているのかも分からない。結果として、高いからではなく「よく分からないから」離脱する人が多かった。本当の問題は料金そのものではなく、決める瞬間に料金が見えないことだった。

My Approach アプローチ

Rather than designing static mockups in Figma, I live-coded functional HTML prototypes to explore the problem space. Complex interactive states — responsive cart panels that transform from side drawers to bottom sheets, multi-line plan configurations with real-time price updates, accordion behaviors with progressive disclosure — these are nearly impossible to communicate in static frames. Code was the design tool. Figma で静止画のモックアップをつくるのではなく、実際に動く HTML のプロトタイプをその場で書きながら問題を探った。横から出るドロワーが画面幅によって下からのシートに変わるカート、回線を足すたびに金額が即座に変わる設定画面、必要なぶんだけ開いていくアコーディオン — こういう動きは、止まった画面では伝えようがない。このときのデザインツールは、コードそのものだった。

Through six prototypes, I systematically explored plan comparison layouts, cart panel architectures, and pricing display patterns. The breakthrough came with the "line item box" pattern — compact mini-cards within the cart that gave each phone line its own visual identity, showing plan, device, and cost at a glance. This pattern made multi-line pricing finally legible. 6本のプロトタイプを通して、プランの比較レイアウト、カートの構造、料金の見せ方をひとつずつ試した。突破口になったのは「ラインアイテムボックス」だ — カートの中に置いた小さなカードが、回線ごとに見た目のまとまりを与え、プラン・端末・金額を一目で示す。これで、複数回線の料金がようやく読めるものになった。

The Brand, Reverse-Engineered into Code ブランドを、コードに書き起こす

Total Wireless is one of several brands under one roof, so its design system was built in Figma as a tight, white-label architecture — a single set of nested components, re-skinned per brand. Powerful and rigorous, but locked inside Figma. It was never handed to designers as code, so as the AI era arrived there was no way to prototype with the real brand in running code. Total Wireless は、ひとつの傘の下にある複数ブランドのうちの一つだ。だからデザインシステムは、Figma 上でホワイトレーベル型として厳密に組まれていた — 入れ子になった一組のコンポーネントを、ブランドごとに見た目だけ差し替える構造である。強力で厳密だが、Figma の中に閉じていた。デザイナーにコードとして渡されることはなく、AI が使えるようになっても、実際のブランドのまま動くプロトタイプをつくる手段がなかった。

So I reverse-engineered it. Working from the publicly visible product, I rebuilt the brand as code: design tokens for color, type, radius, and spacing, wired into a typed shadcn/ui component registry on Next.js. Now an AI — or any engineer — can assemble a new screen and it comes out on-brand by construction: the right navy, teal, and red; the right radii, type, and spacing. そこで、自分で書き起こした。公開されているプロダクトを手がかりに、ブランドをコードとして組み直した — 色・書体・角丸・余白をデザイントークンにして、Next.js 上の型付き shadcn/ui コンポーネントレジストリにつないだ。こうすると、AI でも — 誰が書いても — 新しい画面を組んだ時点で自動的にブランド通りになる。ネイビーもティールもレッドも、角丸も書体も余白も、間違えようがない。

The early live-coded prototypes proved the UX fast, but each was a one-off throwaway. This was the opposite: one reusable system, faithful to the brand and close enough to production to ship — the definitive version of the same idea, and the bridge between the brand and AI-coded prototypes. 最初に書いたプロトタイプは UX を素早く証明できたが、どれも一度きりの使い捨てだった。これはその正反対で、ブランドに忠実で、そのままリリースできる水準の、使い回せる一つの仕組みだ。同じ発想の決定版であり、ブランドと「AI が書くプロトタイプ」をつなぐ橋になっている。

globals.css — brand tokens
@theme inline {
  /* Brand — from the Figma source of truth */
  --font-heading: "Galano Grotesque", "Inter";

  --color-tw-navy-900: #000330;  /* primary text  */
  --color-tw-navy-500: #26358B;  /* brand blue    */
  --color-tw-teal-400: #00C8B7;  /* savings/promo */
  --color-tw-red-600 : #EE0000;  /* Add to Cart   */
  --color-tw-gray-100: #F2F2F2;  /* page surface  */
}
button.tsx — variants mapped to Figma
const buttonVariants = cva(
  "rounded-full font-bold transition-all",
  { variants: {
      variant: {
        default: "bg-tw-navy-900 text-white",      // primary
        cta    : "bg-tw-red-600 text-white",        // Add to Cart
        teal   : "bg-tw-teal-400 text-tw-navy-900",  // savings
      },
  } }
)

Every brand value lives in code. Colors, type, and radii come from tokens extracted from Figma (left); each component maps a Figma variant onto those tokens (right) — so “Add to Cart” is always tw-red-600, never a guess. That constraint is exactly what lets an AI build a prototype that stays on-brand. ブランドの値はすべてコードの中にある。色・書体・角丸は Figma から抜き出したトークンに基づき（左）、各コンポーネントは Figma のバリアントをそのトークンに対応させている（右）— だから「Add to Cart」は必ず tw-red-600 になり、勘で決まる余地がない。この縛りがあるからこそ、AI にブランド通りのプロトタイプを組ませられる。

The Storybook — Live Component Catalog Storybook — 実際に動くコンポーネント一覧

This is where the reverse-engineered system becomes something a team can actually use. The whole thing ships as a browsable styleguide, running live in the page: brand tokens, every component with its variants and states, and guides for pulling components from the registry and tracing each one back to its Figma origin. Open Brand, Components, or Guides and click around — this is the catalog a teammate, or an AI agent, pulls from to build on-brand, every time. 書き起こした仕組みが、チームが実際に使えるものになるのはここからだ。全体を、そのまま見て回れるスタイルガイドとして、このページの中で動かしている — ブランドのトークン、各コンポーネントのバリアントと状態、レジストリからコンポーネントを取り込む手順、そして各コンポーネントが Figma のどこから来たかをたどるためのガイドまで。Brand・Components・Guides を開いて触ってみてほしい — チームのメンバーや AI エージェントが、毎回ブランド通りにつくるために参照するのが、このカタログだ。
