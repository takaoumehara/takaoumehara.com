AI Tools & Skills / superforge

Skill system · 14 Claude Code skills · Model tieringスキルシステム · 14 の Claude Code スキル · モデル階層制御

A multi-agent system built to make AI development repeatable.AIとの開発を再現可能にする、14 の専門役割とモデル階層。

AI coding assistants lose their context the moment a session is cleared, and the quality of the output goes with it. I split development into fourteen specialist skills, gave every subtask a model sized to its difficulty, and required each skill to write its result to a file before reporting back. Rebuilding the same instructions every morning stops being part of the job — and the token bill stops paying for it.AIツールとの対話は、セッションをクリアした瞬間に合意事項や設計意図が失われ、出力の品質が不安定になる課題がありました。私は開発工程を14 の専門スキルに分解し、タスク難易度に応じたモデル割り当てと、成果物の自動永続化を行うオーケストレーションシステムを設計しました。都度の指示組み立てを不要にし、APIトークン消費と品質の双方を最適化しました。

Where it started出発点

Single-model transient chats全てが消える単一モデル対話

Standard workflows pass every task — from business strategy down to a minor text replacement — to a single expensive model. Decisions live only in a temporary chat window, so the same setup gets explained again the next morning.従来のAI対話では、高度な設計判断から機械的なファイル置換まで、全て同一の高額モデルで処理されていました。決定事項は一次的なチャット欄にしか残らず、翌日には同じ説明を繰り返す必要がありました。

High API cost高コスト単一モデル Lost contextスレッド消去で喪失 Ad-hoc prompts都度の手動指示

What it became再設計後の姿

Tiered models & saved assets階層化モデルと成果物の永続保存

Tasks are triaged into five complexity tiers, and the bottom one — bulk text that never touches the repository — is offloaded to a local CLI at no cost. Every skill writes a structured file under docs/, so the context survives a session reset or a switch to another tool.作業難易度を5段階に仕分けし、コード修正を伴わないテキスト処理はローカルの無料CLIへオフロード。各スキルが決定事項を docs/ 内へ構造化ファイルとして自動出力するため、環境を跨いでも文脈が維持されます。

5 model tiers5段階モデル配分 docs/ persistencedocs/ への永続化 0-cost local run無料ローカル実行

The decision意思決定

Task complexity must determine model selection.作業の難易度で、使うモデルを決める。

To settle the trade-off between speed, depth and cost, I gave up on relying on a single model. An orchestration hub reads the task it is handed and assigns it a tier. High-reasoning models are reserved for architectural and business judgment; mechanical work is spread across fast, light ones.AI開発における実行速度・深さ・コストのトレードオフを解消するため、単一モデルへの依存を捨てる判断をしました。タスク内容を受付（オーケストレータ）が判別し、最適なモデル階層へ動的に振り分けるアーキテクチャを導入。高度なビジネス・設計判断だけに高推論モデルを集中させ、機械的な作業は軽量・高速なモデル群に分散させました。

One timeline became a workshop with four rooms.ひとつのタイムラインを、4 つの部屋を持つ工房に。

The old structure was not really a structure. Thinking, building and checking all shared one thread, so nothing showed how far a decision had actually got. The new tree gives each phase its own skills and its own output file — and it is the file, not the conversation, that carries the project forward.旧構造は、構造と呼べるものではありませんでした。思考・実装・検証の全工程が1つのタイムラインに混在し、どこまで決定したかが不透明。新しいツリーは各フェーズに専用のスキルと出力ファイルを与えます。プロジェクトを前に運ぶのは、会話ではなくファイルです。

One long prompt became fourteen skills with a single responsibility each, so the constraints and checks a given job needs can be injected on their own.「一言の長いプロンプト」を「明確な責任を持つ14の単機能スキル」へ。各作業に必要な制約と検証ルールを独立して注入するため。

Four decisions, in the order they were made.決めた順に、4 つ。

01

Fourteen roles and one front desk14 の役割分離と、中央受付ハブ

To stop a single prompt from running away with the whole job, I defined four phases — think, build, test, ship — modelled on how client work is actually staged, and placed fourteen skills inside them. The central superforge skill routes each task.単一プロンプトでの暴走を防ぐため、受託開発の工程になぞらえた「考える・作る・試す・出す」の4フェーズ14スキルを定義。中央の superforge スキルがタスクを自動ルーティングする構造を確立しました。

02

A cost-and-capability matrix, five tiers deep5 段階のコスト・能力マトリクス

Rules for when each model earns its place: Opus for judgment, Fable for long unattended runs, Sonnet for volume, Haiku for fast audits. Text work that never touches the repository moves to the local gemini CLI, which costs nothing to run.各スキルの実行コストを最適化するため、Opus（最高推論）、Fable（長距離自律）、Sonnet（標準量産）、Haiku（高速監査）の使い分けルールを制定。コード変更不要なテキスト処理はローカル gemini CLI（コストゼロ）へ移送可能にしました。

03

docs/ as the single source of truthdocs/ を唯一の真実の source に

So that a project can continue after the conversation is gone, every skill is required to write a specific format of Markdown or HTML into docs/ when it finishes. Switch tools or switch models, and the work resumes immediately.会話セッションが消えてもプロジェクトが進行できるよう、全スキルが完了時に特定フォーマットのMarkdownやHTMLを docs/ 内に出力する制約を付与。ツールやモデルを乗り換えても即座に再開できる基盤を整えました。

04

Refusing the average answer平均解を打破する思考エンジンと、失敗の記憶

To avoid the safe, unremarkable answer a model defaults to, I built in a BreakBias engine that forces ideas past the obvious, and a FailForward memory that learns from past bugs and can be searched before a new one is diagnosed.AI特有の「無難で無害な回答」を避けるため、極端なアイデア発案を強制するBreakBias エンジンや、過去のバグから失敗パターンを学習・検索するFailForward 記憶機構を組み込みました。

The tier is chosen before any agent is spawnedエージェントを起こす前に、階層は決まっている

Judgment costs more than volume, so the two are never billed the same. The bottom tier is the interesting one: work that needs no repository access runs on the local gemini CLI and consumes no Anthropic usage at all.判断は量より高くつくので、同じ単価にはしません。面白いのは最下段です。リポジトリへのアクセスが要らない作業はローカルの gemini CLI で走り、Anthropic の利用量をまったく消費しません。

How AI was usedAIをどう使ったか

The model wrote the scaffolding. The opinions it could not.雛形はAIが書いた。意見の部分は書けなかった。

More than eighteen configurations of the skill set were tried. The test for each was the same: clear the session completely, and see whether the next model could resume at the same quality from the written files alone.スキル構成案は18パターン以上を検証しました。選定基準は一貫して「セッションを完全にリセットしても、出力されたドキュメントだけで次のAIが同じ品質で開発を再開できるか」です。

What AI didAIにさせたこと

Wrote the boilerplate for all fourteen skills, generated the first pass of the documentation in five languages, and ran the test workflows.14スキルの雛形コード記述、多言語ドキュメント（5言語）の初期生成、およびテストワークフローの自動実行。

Where it fell shortAI案のどこがダメだったか

Followed faithfully, the output collapsed toward the polished but familiar — a design or an idea you have seen somewhere before. The sharp product decisions and the strict security and accessibility rules were the first things to fall out.指示を忠実に実行させようとすると、デザインやアイデアが「綺麗だがどこかで見たような平均的で浅い回答」に収縮し、エッジの効いたプロダクト設計や厳格なセキュリティ・アクセシビリティ監査ルールが抜け落ちていました。

What I added人として足したこと

  • The BreakBias engine, which breaks the average idea on purpose平均的発案を強制破壊する BreakBias エンジン
  • The VVA Matrix — visual density and tone made measurable on four axes視覚密度やトーンを定量化する VVA Matrix（4軸設計）
  • FailForward, which tags a bug’s root cause so it is recalled next time失敗の根本原因をタグ記憶させる FailForward の連動設計
  • A sources ledger carrying verification dates, so changes to external models cannot rot the system quietly外部モデルのバージョン変化に耐える Sources Ledger（検証期日台帳）

Considered and dropped検討したが採用しなかった案

A one-click generator全自動ワンクリック生成アプリ

The appeal:魅力: say “build me an app” once, and let the whole pipeline finish in the background.「アプリを作って」と一言入れるだけで、バックグラウンドで全工程が完了する手軽さ。

Why not:捨てた理由: the human is shut out of the decisions that matter — tone, business model — and what comes back is a mountain of code too large to correct.人間が途中の意思決定（デザインのトーン、ビジネスモデルの選択）に関与できず、修正不能な巨大なコードの山が生成されるリスクが高かった。

One giant prompt単一の巨大な万能プロンプト

The appeal:魅力: one file to manage, and the easiest thing in the world to distribute and update.ファイル1つで管理でき、配布や更新が最も容易だった。

Why not:捨てた理由: the context window fills, the instructions begin contradicting each other, and the model quietly skips the security checks and the UI token constraints.コンテキストウィンドウの圧迫と「指示の競合」が発生し、モデルが重要なセキュリティチェックやUIトークン制約を無視する現象が頻発した。

Two things this has not solvedまだ決着していない、2 つ

Both are structural rather than incidental — they are the price of building on top of models someone else ships.どちらも偶発的な不具合ではなく構造的なものです。他人が出すモデルの上に建てる以上、避けられない代償です。

01

The inevitable decay of external model APIs外部モデルAPI仕様の、不可避な経年変化

Model names and API specifications change every few months. A SOURCES.md ledger carrying verification dates keeps the drift visible, but the update logic is not automated — periodic manual or workflow checking is still the running cost of this system.AIモデルの名称やAPI仕様は数ヶ月単位で更新されます。SOURCES.md という検証期日台帳を導入しましたが、自動更新ロジックの完全自動化には至っておらず、定期的な手動またはワークフロー検証の手間が課題として残っています。

02

Visual feedback limits in a CLI agent environmentCLI環境における、リアルタイムUIフィードバックの限界

The HTML and CSS that superforge-ui produces is strong, but in a CLI-first agent environment there is a lag before a human can look at the rendered result and adjust it. Making headless-browser screenshots seamless is the piece still open.superforge-ui によるHTML/CSS出力は強力ですが、CLI主体のエージェント環境ではレンダリング結果の視覚的微調整を即座に人間が確認するループにラグが生じます。ヘッドレスブラウザ連携による自動スクショ取得のシームレス化が今後の宿題です。
