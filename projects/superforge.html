Skill system · 14 Claude Code skills · Model tieringスキルシステム · 14 の Claude Code スキル · モデルの使い分け

A multi-agent system built to make AI development repeatable.AI と一緒につくる作業を、毎回同じ質で繰り返せるようにする仕組み。

AI coding assistants lose their context the moment a session is cleared, and the quality of the output goes with it. I split development into fourteen specialist skills, gave every subtask a model sized to its difficulty, and required each skill to write its result to a file before reporting back. Rebuilding the same instructions every morning stops being part of the job — and the token bill stops paying for it.AI のコーディング支援は、セッションを消した瞬間に文脈ごと消えてしまい、出来上がるものの質も一緒に落ちます。そこで開発の工程を14 の専門スキルに分け、作業の難しさに見合ったモデルをそれぞれに割り当て、どのスキルも結果をファイルに書き出してから返すようにしました。毎朝、同じ前提を一から説明し直す作業がなくなり、その分のトークン代も払わなくて済みます。

Where it started出発点

Single-model transient chats全部消える、単一モデルとの会話

Standard workflows pass every task — from business strategy down to a minor text replacement — to a single expensive model. Decisions live only in a temporary chat window, so the same setup gets explained again the next morning.ふつうのやり方だと、事業の方針を決めるような判断から、ちょっとした文字の置き換えまで、すべてを同じ高価なモデルに投げることになります。決めたことはその場のチャット欄にしか残らないので、翌朝また同じ説明を繰り返すことになる。

High API cost高いモデル1本で全部 Lost contextスレッドを消すと消える Ad-hoc prompts毎回、手で指示を組み立て直す

What it became作り直したあとの姿

Tiered models & saved assetsモデルの使い分けと、残るファイル

Tasks are triaged into five complexity tiers, and the bottom one — bulk text that never touches the repository — is offloaded to a local CLI at no cost. Every skill writes a structured file under docs/, so the context survives a session reset or a switch to another tool.作業を5段階の難しさに分け、いちばん下の段 — リポジトリに触らない大量のテキスト処理 — は、お金のかからないローカルの CLI に回します。どのスキルも決めたことを docs/ 以下のファイルに書き出すので、セッションを消しても、別のツールに移っても、文脈はそのまま残ります。

5 model tiers5段階のモデル配分 docs/ persistencedocs/ に残る 0-cost local runローカルで無料実行

The decision意思決定

Task complexity must determine model selection.作業の難しさで、使うモデルを決める。

To settle the trade-off between speed, depth and cost, I gave up on relying on a single model. An orchestration hub reads the task it is handed and assigns it a tier. High-reasoning models are reserved for architectural and business judgment; mechanical work is spread across fast, light ones.速さ・深さ・コストの三つはどうしても引っ張り合うので、モデル1本に頼るのをやめました。受付役（オーケストレーター）が渡された作業を読んで、難しさの段を決めて振り分けます。設計や事業の判断だけを推論の強いモデルに集め、機械的な作業は軽くて速いモデルに散らす形です。

One timeline became a workshop with four rooms.1本の時系列を、4つの部屋がある工房に。

The old structure was not really a structure. Thinking, building and checking all shared one thread, so nothing showed how far a decision had actually got. The new tree gives each phase its own skills and its own output file — and it is the file, not the conversation, that carries the project forward.以前の構造は、構造と呼べるものではありませんでした。考える・つくる・確かめるがすべて1本の流れに混ざっていて、どこまで決まったのかが見えない。新しい形では、各フェーズに専用のスキルと出力ファイルを持たせました。プロジェクトを前に進めるのは、会話ではなくファイルです。

One long prompt became fourteen skills with a single responsibility each, so the constraints and checks a given job needs can be injected on their own.長い1本のプロンプトを、役割がひとつずつはっきりした14のスキルに分けました。その作業に必要な制約とチェックだけを、単体で差し込めるようにするためです。

Four decisions, in the order they were made.決めた順に、4つ。

01

Fourteen roles and one front desk14 の役割分担と、中央の受付

To stop a single prompt from running away with the whole job, I defined four phases — think, build, test, ship — modelled on how client work is actually staged, and placed fourteen skills inside them. The central superforge skill routes each task.1本のプロンプトが仕事を丸ごと抱えて暴走しないように、受託の仕事の進み方になぞらえて「考える・つくる・確かめる・出す」の4フェーズを決め、その中に14のスキルを置きました。振り分けは中央の superforge スキルが行います。

02

A cost-and-capability matrix, five tiers deep5段階のコストと能力の対応表

Rules for when each model earns its place: Opus for judgment, Fable for long unattended runs, Sonnet for volume, Haiku for fast audits. Text work that never touches the repository moves to the local gemini CLI, which costs nothing to run.どのモデルがどこで働くべきかのルールを決めました。判断は Opus、長く放っておく作業は Fable、量をこなすのは Sonnet、素早い点検は Haiku。リポジトリに触らないテキスト処理は、動かすのにお金のかからないローカルの gemini CLI に回せます。

03

docs/ as the single source of truthdocs/ を、唯一の参照先にする

So that a project can continue after the conversation is gone, every skill is required to write a specific format of Markdown or HTML into docs/ when it finishes. Switch tools or switch models, and the work resumes immediately.会話が消えてもプロジェクトが続くように、どのスキルも終わったら決まった形式の Markdown か HTML を docs/ に書き出す決まりにしました。ツールを変えても、モデルを変えても、そこから即座に再開できます。

04

Refusing the average answer平均的な答えを避けるための仕掛けと、失敗の記憶

To avoid the safe, unremarkable answer a model defaults to, I built in a BreakBias engine that forces ideas past the obvious, and a FailForward memory that learns from past bugs and can be searched before a new one is diagnosed.モデルは放っておくと「無難で当たり障りのない答え」に落ち着きます。それを避けるために、発想を安全圏の外へ押し出すBreakBias エンジンと、過去のバグを覚えていて新しい不具合を調べる前に引き出せるFailForward の記憶を組み込みました。

The tier is chosen before any agent is spawnedエージェントを立ち上げる前に、どの段で走らせるかは決まっている

Judgment costs more than volume, so the two are never billed the same. The bottom tier is the interesting one: work that needs no repository access runs on the local gemini CLI and consumes no Anthropic usage at all.判断は量をこなすより高くつくので、同じ値段にはしていません。面白いのはいちばん下の段です。リポジトリに触る必要のない作業はローカルの gemini CLI で走るので、Anthropic の利用量をまったく使いません。

How AI was usedAIをどう使ったか

The model wrote the scaffolding. The opinions it could not.型はAIが書けた。意見は書けなかった。

More than eighteen configurations of the skill set were tried. The test for each was the same: clear the session completely, and see whether the next model could resume at the same quality from the written files alone.スキルの組み方は18通り以上を試しました。判定基準はいつも同じで、「セッションを完全に消しても、書き出されたファイルだけで次のモデルが同じ質のまま続けられるか」です。

What AI didAI に任せたこと

Wrote the boilerplate for all fourteen skills, generated the first pass of the documentation in five languages, and ran the test workflows.14 のスキルの雛形コードを書くこと、5言語のドキュメントの初稿をつくること、テスト用のワークフローを走らせること。

Where it fell shortAI に任せきると、どこが崩れたか

Followed faithfully, the output collapsed toward the polished but familiar — a design or an idea you have seen somewhere before. The sharp product decisions and the strict security and accessibility rules were the first things to fall out.言われたとおりに素直に進めさせると、出てくるデザインやアイデアが「きれいだけど、どこかで見たもの」に寄っていきます。とがったプロダクトの判断や、厳しめのセキュリティ・アクセシビリティのルールが、まず最初に落ちていきました。

What I added人間の側で足したこと

  • The BreakBias engine, which breaks the average idea on purpose平均的な発想をあえて壊す BreakBias エンジン
  • The VVA Matrix — visual density and tone made measurable on four axes見た目の密度やトーンを4つの軸で測れるようにした VVA Matrix
  • FailForward, which tags a bug's root cause so it is recalled next timeバグの根本原因にタグを付けて覚えさせ、次に引き出せるようにした FailForward
  • A sources ledger carrying verification dates, so changes to external models cannot rot the system quietly外部モデルの変更で静かに壊れないよう、検証日を記録する Sources Ledger

Considered and dropped検討して、やめた案

A one-click generatorワンクリックで全部生成するアプリ

The appeal:良かった点： say "build me an app" once, and let the whole pipeline finish in the background.「アプリを作って」と一言入れれば、あとは裏側で全工程が終わる手軽さ。

Why not:やめた理由： the human is shut out of the decisions that matter — tone, business model — and what comes back is a mountain of code too large to correct.デザインのトーンやビジネスモデルといった肝心な判断から人間が外されてしまい、返ってくるのは直しようのない巨大なコードの山になる。

One giant prompt巨大な万能プロンプト1本

The appeal:良かった点： one file to manage, and the easiest thing in the world to distribute and update.ファイル1つで管理できるので、配るのも更新するのもいちばん楽だった。

Why not:やめた理由： the context window fills, the instructions begin contradicting each other, and the model quietly skips the security checks and the UI token constraints.コンテキストウィンドウがすぐ埋まり、指示同士が矛盾しはじめて、モデルが肝心なセキュリティチェックや UI トークンの制約を黙って飛ばすようになった。

Two things this has not solvedまだ決着していないこと、2つ

Both are structural rather than incidental — they are the price of building on top of models someone else ships.どちらもたまたま起きた不具合ではなく、構造からくるものです。他人がつくったモデルの上に建てる以上、避けられない代償だと思っています。

01

The inevitable decay of external model APIs外部モデルの API は、必ず変わっていく

Model names and API specifications change every few months. A SOURCES.md ledger carrying verification dates keeps the drift visible, but the update logic is not automated — periodic manual or workflow checking is still the running cost of this system.モデルの名前も API の仕様も、数か月単位で変わります。検証日を記録する SOURCES.md を置いてずれが見えるようにはしましたが、更新そのものは自動化できていません。定期的に人かワークフローで確かめる手間が、この仕組みの維持費として残っています。

02

Visual feedback limits in a CLI agent environmentCLI 環境では、見た目の確認が遅れる

The HTML and CSS that superforge-ui produces is strong, but in a CLI-first agent environment there is a lag before a human can look at the rendered result and adjust it. Making headless-browser screenshots seamless is the piece still open.superforge-ui が出す HTML と CSS は十分に強力ですが、CLI 中心のエージェント環境では、描画された結果を人間が見て手を入れるまでにどうしても間が空きます。ヘッドレスブラウザでのスクリーンショット取得を、引っかかりなく回せるようにするのが次の課題です。
