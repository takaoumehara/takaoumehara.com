01 · Problem

The unreadability of machine-translated docs

Automated translation tools produce unnatural phrasing, butchered technical jargon, and mismatched documentation structures that frustrate international engineers.

02 · Transcreation

Rewriting rather than translating

Western developers value concise commands and rapid setup snippets, while Japanese engineering cultures appreciate contextual background, architecture diagrams, and clear dependency scopes.

03 · Terminology

Preserving code symbols and conventions

Ensures programming symbols, variable names, and CLI flags remain untouched, paired with natural katakana conventions that native Japanese developers actually use.

04 · Synchronization

Automated drift detection

Monitors PRs and repository updates to detect when English and Japanese documentation diverge, generating targeted diff proposals to keep documentation in sync.

05 · Impact

Open-source accessibility across borders

Enables solo creators and multinational engineering teams to publish bilingual READMEs, API guides, and contributing workflows effortlessly.
