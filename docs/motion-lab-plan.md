## 0. これは何の企画か

「ローディングやトランジションのパラメータをいじって、プリセットを見比べて、
クリックして試して、どれがいいか決める」——その**チューニングの過程そのものを
作品にする**プロジェクト。Web でモーション（ローディング演出・画面遷移）に何ができるかを
公開の「楽器」として触れるようにし、決定の過程・比較・却下案までを記録として残す。

Takao のこれまでのテーマ（インタラクティブメディアデザイナーとしての 0→1、
「作品を人前でその場で操作する」体験設計）と地続きで、
**このサイト自身が、彼が普段作っている「画面を共有しながら操作する作品」の一つとして
振る舞う**ようになる。プレイヤーは訪問者、素材は自分自身のサイトのモーション。

## 2. コンセプト

- **チューニングという行為そのものが作品**: プリセットを選ぶ、パラメータのスライダーを
  動かす、A/B で見比べる、「これだ」と決める——この一連の操作を、訪問者が追体験できる
  形で公開する。舞台裏（試作過程）を見せる作品であり、完成した1つの演出を見せる作品ではない。
- **公開された「楽器」**: Web 上でローディング/トランジションに何ができるかを、
  訪問者自身が触って確かめられるインストゥルメントにする。パラメータ→見た目の対応を
  身体化させる。
- **Takao の文脈との接続**: 「インタラクティブメディアデザイナーとして、0→1 を自分の手で
  動かして確かめる」という彼の一貫した姿勢の、**サイト自身への適用**。彼が日頃作っている
  「その場で操作して確かめる」体験設計を、自分のポートフォリオという媒体でもう一段
  メタにやる。
- **接地点**: このサイト自体の「起動」と「ページ遷移」が実験台であり第一の成果物。
  `docs/motion-archive.md` で洗い出した過去の実装（現存/削除済み含む）が、最初の
  「スタディ」群になる——ゼロから作るのではなく、彼が過去に頑張って作ったものを
  掘り起こして、並べて、選び直す。

## 3. フェーズ

### Phase 0（進行中）— このサイト自身のローダー/トランジションを JSON 化
- **今まさに他エージェント（M2）が着手**: `src/data/motion.json`（パラメータの単一の
  置き場）+ `src/scripts/motion-lab.js`（隠しチューニングパネル、`?lab=1` でのみ有効）。
- 現行の `src/scripts/motion.js` のチョレオグラフィ（box→media→text の duration・遅延
  レンジ・イージング）と `src/styles/transitions.css` の起動/リビール定数を、
  ハードコードされた値から JSON 駆動の値に切り出す作業。
- Takao はこのパネルで数値をいじりながら気に入った設定を見つけ、その JSON を
  エージェントに送り返す——つまり **Phase 0 が最初の「チューニング・セッション」の記録**
  になる。この記録の残し方は §6 の「捕捉すべきもの」を参照。
- **完了条件**: `?lab=1` でパネルが開き、`motion.json` の値をライブに動かせて、
  Takao が「これで行く」という設定を決められる状態。

### Phase 1 — 単独の Lab ページ/アプリ（公開）
- サイトの隠しパネルとは別に、`/lab`（または独立ページ）として**一般公開**するアプリ。
- **プリセット・ギャラリー**: Phase 0/§Phase 2 で溜まったスタディを並べて選べる一覧。
- **URL に設定を埋め込んで共有**: 設定 JSON を URL のハッシュ（`#cfg=...`）に
  base64/圧縮して載せ、リンクを送るだけで同じプリセットを他人の画面で再現できる。
- **録画/書き出し**: `MediaRecorder` API で GIF/WebM としてその場でエクスポート。
  作品として切り出して SNS 等に貼れる形にする。
- **並べて比較（A/B）**: 2つの設定を左右または前後で同時に再生し見比べられるビュー。
- **タイムライン・スクラバー**: アニメーションの再生位置を手でドラッグして止め・戻し・
  コマ送りできる（デバッグでも見せ物でもある）。

### Phase 2 — トランジション・ラボ（View Transitions 特化）
- **View Transitions API** を軸にした専用セクション: 同一文書内（SPA的）と
  クロスドキュメント（通常のページ遷移、`docs/page-transitions.md` の方式）の両方を
  同じ Lab の中で切り替えて試せるようにする。
- **共有要素モーフ（shared-element morph）**、**方向つき（direction-aware）**遷移を
  作る——これはゼロからの新規実装ではなく、`docs/motion-archive.md` B2「Throw/Return」
  と B3「data-nav-dir」の**復元・再構成**が土台になる（一度作って、一度捨てて、
  もう一度作り直す価値があると判断したものとして扱う）。
- **「スタディ」のライブラリ**: 各スタディは 1つの通し番号・名前・設定 JSON・作成日・
  Takao の短いメモを持つカードとして蓄積する。`docs/motion-archive.md` の各項目
  （A1〜E）が、そのままスタディ #001〜のシードになる——つまり Task 1 のアーカイブが
  Phase 2 の初期コンテンツそのもの。

### Phase 3 — サイト上のプロジェクト詳細ページとして公開
- サイトの詳細ページ・フォーマット（`docs/project-page-format.md` 準拠、
  現行の共有ディテールテンプレート）に則って、Motion Lab を1本のプロジェクトとして掲載。
- **ティーザー = Lab のライブ埋め込み**（静止画のスクリーンショットではなく、
  実際に動くプレビューをそのままティーザーに使う——「操作できるものは操作させる」）。
- 制作過程の write-up（このプロセス自体が作品、というコンセプトの言語化。
  Phase 0〜2 で溜めた記録がそのまま原稿の材料になる）。
- 余力があれば OSS パッケージとして切り出し（`motion.json` のスキーマ + 再生エンジン
  部分を、他のサイトでも使える形にする）。

## 6. Phase 0 の間に残しておくべきもの（将来のケーススタディ用）

チューニングの過程そのものが作品、という前提に立つと、**過程の記録を残し損なうことが
最大のリスク**。以下をルーティンとして残す。

### キャプチャ・チェックリスト（各チューニング・セッションごとに）
- [ ] Before/After のスクリーン録画（変更前・変更後、同じ操作で1本ずつ）
- [ ] そのときの `motion.json`（日付付きで保存。上書きせず追記）
- [ ] Takao の判断理由の一言メモ（「なぜこっちを選んだか」— これが後の write-up の核）
- [ ] 却下した案も残す（「良かったが選ばなかったもの」は完成物より雄弁なことが多い）

### フォルダ規約
```
docs/motion-lab/
  journal/
    2026-09-27.md     ← その日のセッションメモ（判断理由、次にやること）
    2026-09-28.md
  configs/
    2026-09-27-a.json ← その時点の motion.json のスナップショット
    2026-09-27-b.json
```
- `journal/YYYY-MM-DD.md` は「その日、何を試し、何を選び、何を却下したか」を短く書くだけ
  でよい（1セッション5行程度でも可）。
- `configs/` は `motion.json` の名前付きスナップショット。後で「#003 を今の値と比べたい」
  が必ず発生するので、上書きせず増やしていく。

## 7. リスク

- **パフォーマンス**: WAAPI/View Transitions は基本的に GPU 合成可能な
  `transform`/`opacity`/`clip-path` に留める（`docs/motion-archive.md` A3 で退場した
  `filter: blur` の教訓——本番サイトのルールとして既に確立済み。Lab では「禁止事項を
  試して見せる」比較用途に限定し、本番プリセットには持ち込まない）。
- **アクセシビリティ**:
  - `prefers-reduced-motion: reduce` は現行実装（`transitions.css`, `motion.js`）で
    既に全面対応済みだが、Lab で新しく作るプリセットは**全て**この分岐を持つことを
    プリセットのスキーマレベルで強制する（「reduced-motion 版を書かないと保存できない」
    くらいの制約が望ましい）。
  - **WCAG 2.2.2（Pause, Stop, Hide）**: 5秒を超えて自動再生し続けるモーション
    （例: プリセット・ギャラリーの自動巡回、A/B 比較の自動ループ）には**一時停止/停止**
    の手段を必ず用意する。
  - **WCAG 2.3.1（Three Flashes or Below）**: 明滅・点滅系のプリセット
    （`mo-dots`, `caret-blink`, `obPulse` 系列）は 1秒あたり3回を超える閃光にならない
    速度に制限する。既存実装は全て 1Hz 未満で安全域だが、Lab でユーザーが速度を
    自由に上げられるようにする場合は**上限値をスキーマで固定**する。
  - **CLS（レイアウトシフト）**: D1 のクリップワイプは要素のボックスサイズを変えない
    設計（現行実装のまま踏襲）。新規プリセットも「見た目は動くがレイアウトは動かない」を
    デフォルトにする。
- **スコープの肥大化**: Motion Lab は本編サイトのレンダリング完了より**優先度は下**
  （Takao の指示どおり）。Phase 0 は本編の一部として自然に進むが、Phase 1 以降へ
  進むのは本編が落ち着いてから、と明確に区切る。

## 8. 技術メモ

- **WAAPI**（`element.animate()`）: 現行 `motion.js` の主力。JS 側でタイミングを
  完全に制御でき、`fill: "backwards"` で「終わったら自然な状態に戻る」設計と相性が良い。
  Lab のプリセット再生エンジンもこれをベースにする。
- **View Transitions API**: 同一文書内（`document.startViewTransition()`）と
  クロスドキュメント（`@view-transition { navigation: auto }` + `pageswap`/`pagereveal`）
  の両方を Phase 2 で使う。名前の一意性制約（1文書に同名は1つまで）は
  `docs/page-transitions.md` で既に踏んだ地雷なので、Lab のスタディ管理でも
  同じ検査（テスト相当のチェック）を用意する。
- **フレームワークなし**: 現行サイトの方針（vanilla JS/CSS）を Lab にも適用する。
  外部モーションライブラリ（GSAP, anime.js, Lottie 等）は今回のアーカイブ調査では
  リポジトリ内に使用実績が見当たらなかった——導入するなら Phase 1 で明示的に検討する
  判断ポイントとして扱う（このドキュメントでは導入を前提にしない）。
