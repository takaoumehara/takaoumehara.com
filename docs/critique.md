## 🔥 THE ROAST

### 原因 1: 価値の芯が、測れないものを約束している
- **[契約は結べない]** `judgeMotion` の state は `{config, glossary, rules}`。端末もフレームも無い。「中位のスマホで 1.2 秒を超えない」は Jev の推定であって計測ではなく、`wait` の score は 0〜3 の体感ルーブリック。product-idea.md は「保証して売る」「SLA 型」と書いたが、根拠になる計測（Long Animation Frames の beacon）は Hero 1 の後半に置かれている。順番が逆。
- **[判定と検証を混同している]** `readable`「1 秒で本文が読めるか」も、config の `text.holdMs` と `cps` から推定するだけ。実際に読めるかは Playwright で測れる（この repo には既にある）。測れるものを AI に「感じさせて」いる。

### 原因 2: 「仮想サイト」が、まだ Takao のサイトでしかない
- **[5 人の便利に届かない]** `/lab/stage` はレール＋ペインの自サイト縮小版。他人がここで「採る / 捨てる」を 8 回押しても、出てくるのは**Takao のサイトの読み込み**の好み。自分のサイトに何が起きるかは想像するしかない。基準 (A) に対して、いまの仕様は 3 分の玩具。
- **[材料の幅が 1 系統]** 11 プリセットは全部 box-first の変奏。「ユニークな表現を作れる道具」の材料としては細い。過去の演出 6 系統（H1〜H3、B 系）を持ち替え可能にする library-plan §5 が**未着手**で、それが唯一「他に無い材料」なのに、product-idea.md では脇役。
- **[持ち出しが「貼る」しかない]** JSON を AI に貼る、は Takao 自身のワークフローでは成立するが、5 人のうち何人が「JSON を Claude に貼って自分のサイトを書き換える」か。CSS / WAAPI / GSAP のコードで出す（Workhorse A-F7-2 / C-S19-1 / D-S19-1、事業軸 13）の方が一般の便利に近いのに、選んだ方向から落ちている。

### 原因 3: 事業の骨格が、就職の材料を押しのけた
- **[採用担当が見るのはデモ]** Principal Creative Technologist / design engineer の採用で効くのは、60 秒で触れて「うわ」と言わせる公開デモと、その作り方の物語。「購読と従量」「beacon」「MCP 往復」は、面接では 1 行の補足にしかならない。BreakBias の決定 2（一般向け・課金）を最優先に置いたせいで、Hero 1（Living Spec）が収益層として上に来た。本人は今日それを「二の次」に戻した。**方向の前提が変わったので、選んだ順番も変わる。**
- **[公開されていない]** 就職に効くには公開が要る。`visibility: private`、`draftPagesBuilt()` で本番はビルドしない。公開の手順は記録にあるが、誰も予定に入れていない。
- **[過程が最強の材料なのに、見せる形が無い]** 313 セルの台帳、殺した理由が全部見える HTML、9 件の誤殺を戻した救済パス — これは「AI をどう使って考えたか」の証拠として、2026 年の採用で一番珍しいもの。いまは `docs/` に埋まっている。

### 原因 4: 決定の 6 つが、仕様に均等に反映されていない
- **[決定 3（AI に相談・生成・混合）が入口に無い]** 選んだ順番は「選ぶ → 契約 → 生きた仕様」。生成も混合も Hero 5 として後回し。2026 年の採用でデモに AI が「判定役だけ」なのは弱い。Jev は既にあるのだから、生成 → Jev でふるう、を 1 本の関数にする方が「契約」より先に価値になる。
- **[決定 6（モバイル既定 ON）と 116 個のパネルは両立しない]** フロートする 116 スライダーはスマホで使えない。「採る / 捨てる」がモバイルの唯一の UI になるはずなのに、product-idea.md はそれを「入口」としか書いていない。
- **[音が Lab に落ちたのは正しいが、デモには効く]** 基準 (B) は「驚き」を含む。既定オフの、押した時だけ鳴る 1 音は、コスト 1 日で wow を上げる。事業の物差しで Lab に落ちたものが、就職の物差しでは拾える。

### 原因 5: 言葉が内向き
- **[「生きている仕様」「動きの契約」は社内語]** 採用担当にも 5 人の友人にも通じない。Motion Lab の 1 行は「自分のサイトの読み込みと遷移を、選ぶだけで作って持ち帰れる」で止めるべきで、契約も購読も看板に出さない。

## 「普通のブレストで出る道具」は通るか

普通に出る案: **プリセット一覧 ＋ スライダー ＋ 「こんな感じにして」欄 ＋ CSS / GSAP コードの書き出し ＋ 共有リンク**。要するに Animista / loading.io / uiverse に AI 欄を足したもの。

| 基準 | 判定 | 理由 |
|---|---|---|
| (A) 5 人が便利 | **通る** | Animista 型は実際に何千人も使っている。自分のサイトに貼れるコードが出る、それだけで便利。差別化は基準に含まれていない |
| (B) 就職に有利 | **通らない** | 「Animista をもう一度作りました」は Principal 級の話にならない。既にあるものを再現した、と読まれる。AI 欄を足しても v0 の劣化版 |

**現段階の仕様（選んだ方向）**:

| 基準 | 判定 | 理由 |
|---|---|---|
| (A) 5 人が便利 | **いまは通らない** | 舞台が Takao のサイト、持ち出しが JSON 貼り、公開されていない。3 つとも直せば通る |
| (B) 就職に有利 | **半分** | 材料（過去の演出の復元）と過程（313 セル）は他に無い。ただし公開デモが無く、看板が「契約・購読」になっている |

結論: **普通の案は A だけ、現段階の仕様は B の半分だけ。どちらも 2 つ同時には通っていない。** 両方通す形は、両者の足し算ではなく、下の絞り込み。
