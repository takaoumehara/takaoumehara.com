# Studio Oker 方向 — ランディングページの作り直し

> Written by: superforge-ui · 2026-08-22
> 対象: `index.html` と `assets/play-tiles.js`。カテゴリー名のみ全ページ。
> 参照: refero.design の Studio Oker スタイル（oker.com 由来）。オーナーが
> `DESIGN.md` / `tokens.json` / `variables.css` / `theme.css` として支給。

---

## 0. 結論

ランディングページを**純黒のギャラリー**に作り直した。白のタイポ、
スカーレット `#e4002b` を1画面1滴、角丸ゼロ、影ゼロ、120/240px のリズム。

**捨てなかったもの**: Intent Console と6つの canvas ライブタイル。
どちらもこのサイトで最も強い資産で、方向転換のたびに作り直すものではない。
Oker の語彙に**翻訳**した（§2）。

**捨てたもの**: DM Serif Display（セリフ）、`.rr` リビールシステム、
`press-frame`、塗りのあるボタン、クリーム／白の面、グラデーションの
パレット6プリセット。

---

## 1. 支給された仕様のうち、そのまま守った規則

リファレンスの Do / Don't は緩めずに実装した。CSS 冒頭にも同じリストがある。

| 規則 | 実装 |
|---|---|
| 背景は `#000000` のみ。灰色の面を作らない | `--pure-black` 一色。`--soft-black` は `.post-img` の読み込み前だけ |
| 角丸は全て 0 | `--radius-*` は定義せず、`border-radius` を1箇所も書いていない |
| 影・グロー禁止。奥行きは「空白」で作る | `box-shadow` ゼロ。分離が要る所はヘアライン |
| スカーレットは配給制 | 赤パネル1枚、`.chip` のアクティブ点、`.dot-link` の6px点のみ |
| ウェイトは 300 と 400 だけ | `--w-light: 300` / `--w-regular: 400`。600 以上を使っていない |
| ボタンに塗りを使わない | `.dot-link` — 赤い点が「ボタンの形をしないボタン」 |
| 箇条書きの記号を使わない | Services とカテゴリーは素の積み上げテキスト |

### フォント

NextBook はスタジオ専用書体で入手できない。リファレンスが代替として
**Söhne または Inter** を挙げているので Inter（300/400）を採用。
日本語は Noto Sans JP（300/400）。

**日本語には負のトラッキングを掛けていない。** `-0.02em` は欧文の
ためのもので、和文に掛けると字間が詰まりすぎて読みにくくなる。
`html.lang-jp` で `letter-spacing: 0` に戻し、行送りも上げている。

## 2. 翻訳したもの — 捨てずに Oker の語彙に置き換えた

### Intent Console

以前はチップ（枠線付きボタン）の並び。Oker には枠線付きのチップが無い。
リファレンスの **Services List**（「記号も先頭文字も無い、素の文字列の
積み上げ」）がそのまま使える形だったので、そこに移した。

- 5つの意図 → 枠も塗りも無い縦積みテキスト
- 選択中の1つ → スカーレットの点（`.chip[aria-pressed="true"]::before`）
- 回答の数値 → リファレンスの **Studio Stat Block**（ラベル／値、罫線も箱も無し）
- CTA → 赤い点のリンク

ロジック（`DATA`、タイプライタ、ルート演出、EN/JP 同期）は無改変で移設。
1点だけ修正: リンク文字列を `<span>` の中に書くようにした。以前は
アンカー自身の `textContent` を書き換えていて、この方向では
`::before` の赤い点が消えてしまうため。

### ライブタイル

`index.html` に埋め込まれていた canvas コード（約520行）を
`assets/play-tiles.js` に切り出した。変更は**地の色を `#0d0d12` →
`#000000`** にしただけ。Oker はページ全面が純黒なので、タイルが
自分の地色を持っていると、そこだけ 5% 明るい四角として浮く。

作品自体の色（Rakugaki の紫、Koe Baku の赤金）はそのまま。
リファレンスも写真は「自然のまま、加工しない」としている。

## 3. リファレンスから外した唯一の判断 — タイルのヘアライン

リファレンスは「タイルに枠線は要らない。**写真の縁がカードの縁**」と書いている。
Oker の壁は写真で埋まっているので、これは正しい。

このサイトの壁は違う。9枚のうち6枚が**ほぼ黒い canvas** で、
自分の縁を持っていない。枠線無しで実装したところ、壁全体が
「黒い霧の中に文字と小さな図形が浮いている」状態になり、
どこからどこまでが1つの作品なのか読めなかった（実測して確認した）。

リファレンス自身が逃げ道を用意している:

> 分離が必要なときは、`#484848` または `#a0a0a0` のヘアラインを1本使う。
> これは意図的な反スキューモーフィズムの立場である。

そこで**全タイトルにヘアライン1本**を入れた。影でも段差でもトーンの
持ち上げでもない。リファレンスが唯一許可している分離手段。

実装上の注意: `outline` ではなく `border` を使っている。canvas は
`position: absolute` の子要素で、`outline` の上に描画されてしまうため。

## 4. 壁のグリッド — アスペクト比ではなく行スパン

最初はタイルごとに `aspect-ratio`（16/10、1/1、3/4）を指定した。
タイル単体は正しくなるが、**壁が壊れる**。grid の行は最も背の高い
要素に合わせるので、同じ行の低いタイルの下に穴が空く。

共通の行単位（`grid-auto-rows: clamp(104px, 11.5vw, 188px)`）＋
`grid-auto-flow: dense` に変更。タイルは列と行のスパンで大きさを持つ。

**列数は 12 の倍数に揃えてある**（9タイル = 2+1+1+2+1+1+1+1+2）。
半端だと最後の行に空セルが残り、それは「余白」ではなく「穴」に見える。
タイルを足すときは、この合計を 4 の倍数に保つこと。

## 5. カテゴリー5つ

オーナー指定。全ページのナビ・フッター・パンくずに反映済み（272箇所）。

| # | 名前 | ページ | 件数 |
|---|---|---|---|
| 01 | Interactive Experience | `interactive.html` | 8 |
| 02 | AI Products | `ai-products.html` | 5 |
| 03 | AI Tools & Skills | `ai-tools.html` | 7 |
| 04 | Product Design | `work.html` | 13 |
| 05 | Branded Experience | `brand.html` | 12 |

改名: `Interactive` → `Interactive Experience` /
`AI Tools` → `AI Tools & Skills` / `Brand & Visual` → `Branded Experience`
（和文は「ブランド体験」）。

**「AI tools/skills」の表記だけ判断が入っている。** 指定はスラッシュ
表記だったが、他の4つが Title Case の語なので `AI Tools & Skills` に
揃えた。スラッシュに戻すなら1箇所（テストの `CATEGORY_NAV`）で済む。

件数はテストが**カテゴリーページの実際の中身と突き合わせて**いる
(`the landing page lists the five categories with counts its pages can back`)。
数字だけ直して中身が伴っていない状態は落ちる。

## 6. 未着手 — 次にやること

**ランディングページ以外は旧デザインのまま。** 現在サイトは、
黒いトップページと、白い下層ページが同居している。意図的な段階移行で、
方向が承認されてから残りを移す。

順序:

1. カテゴリーページ5枚（`interactive` / `ai-products` / `ai-tools` /
   `work` / `brand`）— 共通シェルを持つので、`.wall` と `.post` を
   共有 CSS に出せば一括で移せる
2. `about` / `contact`
3. ケーススタディ約35枚 — keynote-slide-page の方向とどう両立させるか
   を先に決める必要がある。ここは黒一色にすると作品の写真が死ぬ可能性がある

## 8. コントラスト — 実測値と、1つの未解決

`#000000` に対する実測（WCAG 2.x の式）:

| トークン | 値 | 比 | 判定 |
|---|---|---|---|
| `--bone-white` | `#ffffff` | **21.0:1** | AAA |
| `--fog-gray` | `#a0a0a0` | **8.03:1** | AAA（本文可） |
| `--scarlet` | `#e4002b` | **4.33:1** | 大きい文字は AA、本文サイズは不足 |
| `--graphite` | `#484848` | **2.30:1** | 文字色としては AA 不可 |

**未解決が2つある。どちらもリファレンス由来なので、勝手に直していない。**

1. **`--graphite` を文字色に使っている箇所** — `.route-step`（未点灯）、
   `.cat-no` の番号、言語スイッチの非選択側。2.30:1 で、装飾なら許容、
   情報なら不可。`--fog-gray` に上げれば解決するが、「消えている状態」
   と「点いている状態」の差が弱くなる。

2. **赤パネルの `#e4002b`** — 4.33:1。あの文字サイズ（38–88px）なら
   WCAG の大文字基準 3:1 を満たすので問題ない。ただし
   `.dot-link::before` の 6px の点も同じ赤で、これは点であって文字では
   ないため対象外。本文サイズの赤文字は1箇所も作っていない。
