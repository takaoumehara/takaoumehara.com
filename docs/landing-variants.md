## 現状の実装差

**3案とも遷移が通っている。** 共有ハンドオフ層（`assets/handoff.js` /
`docs/page-transitions.md` §6）を A・B・C と 41 のプロジェクトページに入れた。
案ごとに**形が違うのは意図的**で、層は1枚しかない。

| 案 | 遷移の形 | 理由 |
|---|---|---|
| A | 写真が全画面へ拡大 → 遷移先が同じ画像で開く | クリーム地で色を配給しているのに全画面に色を流したら、A の主張と矛盾する。カードで唯一その案件の持ち物なのは写真 |
| B | ホバー時点で遷移先の色が全画面。クリックは壊さないだけ | 元からの方式。ただし**フィールドの箱をビューポートに統一**して、色が切れる問題を潰した |
| C | パネルの画像がそのまま静止 → 遷移先が同じ画像で開く | パネルは既に全画面画像なので、飛ばすものが無い。動かさないのが正解 |

## C の上限について（ユーザーの質問への回答）

**「C はプロジェクト数がすごく限られる」— 正しい。** ただし理由はレイアウトではなく、
**1件＝1画面ぶんのスクロール合意**という構造にある。

- **6件** — 快適。intro + 6 + 末尾で 8 画面
- **9件くらい** — 上限。ここを超えると「まだ続くのか」に変わる
- **34件** — 不可能。リールではなく人質になる

そこで**逃げ道を実装した**: リールの最後の1画面を**インデックスパネル**にして、
見せなかった残りをリスト密度で渡す（3列 × 7件 + 各セクションへのリンク）。
これで「C を採る = 6件しか出せない」ではなく、
**「C は上位6件の見せ方で、残りは1画面で引き渡す」**という構成になる。

混成案（Open questions 1）に対する部分回答でもある: B のリスト構造は、
C の最終画面としてそのまま入る。
