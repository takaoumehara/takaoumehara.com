## 0. 決まったこと

1. **スライド形式はやめる。** ページ送りのデッキも、keynote 風の全画面スライドも使わない。
   普通に上から下へ読めるスクロールページに統一する。
   - 削除済み: `ela-quests-slides-preview.html` / `verizon-totalwireless-slides-preview.html`
   - 要変換: `projects/cli-studios.html`（`<main class="deck">` のページ送り）
2. **骨格は Amazon Fire TV を出発点に、さらに削る。**
3. 全 34 ページをこの型に合わせる。

## 1. なぜスライドが機能しなかったか

| 症状 | 原因 |
|---|---|
| 何枚あるか分からず、読み終わりが見えない | ページ送りはスクロールバーを殺す。残量が読めない |
| 検索・リンク・引用ができない | 1 枚 1 枚に URL が無い |
| スマホで破綻する | スライドは固定比率。縦長画面に入らない |
| 画像を大きく見せるための形式なのに、文章が入ると読みにくい | スライドは「話す人がいる」前提の形式。ポートフォリオには話す人がいない |

**ポートフォリオのページには、読み手しかいない。** だから形式は文書であってスライドではない。

## 2. 骨格

上から順に、これだけ。増やさない。

```
breadcrumb            ← Section / Project name
hero（暗い帯）
  tags                ← 最大 4 個
  h1                  ← 案件名。1 行に収める
  summary             ← 2 行以内
  cta                 ← 0〜2 個（Live / Prototype / Repo）
  meta                ← ROLE / YEAR / CONTEXT / STACK の 4 列
body                  ← 下の 5 種類のブロックだけを積む
prev / next
footer
```

## 3. body に置けるブロック（5 種類だけ）

| ブロック | 使うとき | 中身 |
|---|---|---|
| `.pj-prose` | 文章 | 見出し 1 つ ＋ 段落 2 つまで |
| `.pj-media` | 画像・動画・サイト埋め込み | 1 点 ＋ キャプション 1 行 |
| `.pj-facts` | 数字 | 2〜4 個。数字と 1 語のラベル |
| `.pj-split` | 前後比較・2 択の対比 | 左右 2 枚（スマホでは縦） |
| `.pj-contrib` | 自分がしたこと／チームがしたこと | `src/data` の `contribution` と同じ分け方 |

**これ以外のブロックを足さない。** 足したくなったら、それは 5 つのどれかで表せる。

## 4. 規則

- 本文の列は **1200px**（サイト全体と同じ `--col`）。ヒーローの暗い帯だけ全幅。
- 画像は **3:2**。横長の実物スクリーンショットは 16:9 のまま `.pj-media` に置く。
- **1 セクション = 1 主張。** 見出しは主張そのものを書く（「課題」ではなく「カートが料金を隠していた」）。
- 段落は 3 行まで。超えたら 2 つに割るか、`.pj-facts` に出す。
- `reveal-on-scroll` は使わない。**JS が動かなくても全部読める**こと。
- 数字は `src/data` の `metrics` にあるものだけ。無い数字は書かない。

## 5. もう一つの問題 — シェルが 34 回コピーされている

変換に入る前に測った事実:

**34 ページすべてが、ナビ・言語スイッチ・フッターの CSS を自分の `<style>` の中に持っている。**
カテゴリページで直したのと同じ種類の欠陥が、プロジェクト側にそのまま残っている。
今回のナビ修正が 51 ファイルの一括置換になったのは、これが理由。

だから変換は 2 段階になる:

1. **`assets/site-base.css` を切り出す** — トークン、ナビ、言語スイッチ、フッター。
   34 ページの `<style>` からその部分を削り、この 1 枚を読ませる。
   （生成ページ側は `src/render/lens.css` が既にこの役割を果たしている。
   最終的には 1 枚に寄せるが、まず重複を止める）
2. **本文を §2 の骨格に寄せる** — `assets/project-page.css` を使う。
