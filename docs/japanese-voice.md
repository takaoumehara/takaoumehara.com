> Written by: superforge (T1) · Last updated: 2026-09-11

## 0. なぜこの文書が要るか（実測）

| | 件数 |
|---|---|
| 素の英語文字列（`"..."`。JP 表示でも英語が出る） | 216 |
| EN/JP ペア（`{en, jp}`） | 57 |

**日本語ページの 79% は英語だった。** 「不自然な日本語」以前に、日本語になっていない。

さらに、その 21% のうち Phase 1 で新しく書いた分が実際に不自然だった。原因は
「英語を日本語に翻訳した」から。**日本語で考え直していない。**

## 1. 手本 — 既存ページの日本語（これが正）

`interactive.html` などに元からある日本語は良い。これを基準にする。

```
声 · 表情 · 身体 · 手描きの線 · その場のスマホ全部
手元より大きな画面
ほぼ AI ではありません。通信とトラッキングとタイミングの仕事です。
勝ち負けも点数もない
コードを読むだけ — アプリもアカウントも不要
42 名・6 ブランドのデザイン組織の働き方を変えた、10 エージェントの艦隊。
```

何が効いているか。

1. **具体名詞で並べる。**「声・表情・身体・手描きの線」。抽象語（体験、価値、ソリューション）が無い。
2. **否定してから言い換える。**「ほぼ AI ではありません。通信とトラッキングとタイミングの仕事です。」
3. **直訳しない。** "a screen bigger than the one you are holding" →「手元より大きな画面」。
   英語の関係節を、日本語の連体修飾に潰している。
4. **数字が先、体言止め。**「42 名・6 ブランド…10 エージェントの艦隊。」
5. **一文が短い。** 平均 30 字前後。

## 2. 反面教師 — Phase 1 で書いてしまった日本語

```
✗ プロダクト・デザイン・ビジネス・新しい技術をまたいで働くデザイン & AI
  エグゼクティブ、そしてベンチャービルダー。
✗ ベンチャービルディング、エグゼクティブアドバイザリー、フラクショナルな
  リーダーシップ、そして手を動かす実験を通して
✗ 三十分話す価値のある問い
✗ 人が実際に反応できるコンセプト・プロトタイプ・プロダクト・ベンチャー・体験に
  変えていく
```

診断。

| 症状 | 正体 |
|---|---|
| カタカナの羅列で意味が入ってこない | 職能名を**音写**しただけ。「エグゼクティブアドバイザリー」は日本語ではない |
| 中黒がやたら多い | 英語の `A, B, C and D` をそのまま中黒に置換した |
| 一文が 60 字を超える | 英語の一文を一文のまま訳した。日本語では切る |
| 「〜していく」「〜すること」 | 英語の動名詞をそのまま名詞化した癖 |
| 「三十分」 | Claim Guard が「30」を弾いたのを回避するための小細工。**日本語を壊してまで通す検査は設計が悪い**（§6） |

## 3. 規則

### 3.1 長さ

| フィールド | 上限 | 文の数 |
|---|---|---|
| `hero.title` | 20 字 | 1 |
| `hero.body` | 120 字 | 2〜3 文 |
| `summary` | 100 字 | 2〜3 文 |
| `angles.*` | 110 字 | 2〜3 文 |
| `metrics[].label` | 20 字 | 体言止め |
| `capability.note` | 45 字 | 1 文 |
| `cta.title` | 30 字 | 1 文 |

一文 40 字を超えたら切る。読点で繋がない。

### 3.2 カタカナ語

**使ってよい**（日本語として定着している）:
プロダクト・デザイン・ブランド・プロトタイプ・チーム・クライアント・ツール・
エージェント・インタラクティブ・コンセプト・アプリ

**使わない**（音写であって日本語ではない。右を使う）:

| ✗ | ○ |
|---|---|
| ベンチャービルディング | 事業を立ち上げる／新規事業づくり |
| エグゼクティブアドバイザリー | 経営への助言 |
| フラクショナルリーダーシップ | 週の何日かを預かる形での参加 |
| ビジネストランスフォーメーション | 事業のつくり替え |
| ステークホルダー | 関係部署／決裁者（文脈で選ぶ） |
| オペレーション | 運営 |
| ソリューション | （削る。何を作ったか書く） |
| バリュー／インパクト | （削る。何が変わったか書く） |

**英字のまま置く**（技術用語として通用し、訳すと劣化する）:
AI · UX · CX · 0→1 · B2B · B2C · MCP · Figma · Gemini · NotebookLM

### 3.3 やらないこと

- 英語の一文を一文で訳さない。**内容だけ取って日本語で書き直す。**
- 中黒の羅列は 4 つまで。5 つ以上並べたくなったら、それは文にすべき内容。
- 「〜を通して」「〜における」「〜に関して」— ほぼ全部削れる。
- 敬体（です・ます）と常体（だ・である）を混ぜない。**このサイトは常体を基本**とし、
  CTA など読者に話しかける箇所だけ敬体にする。
- 主語「私は」を毎文書かない。日本語は主語を省ける。
- 事実は EN と JP で一致させる。**JP 側だけに数字や成果を足さない**（Claim Guard は
  EN/JP 両方を見る）。

### 3.4 書き出しの型

うまくいく順序がある。

```
[何だったか] → [何をしたか] → [何が変わったか]
```

例（Festival）:
```
✗ COVID で 2 年止まった学校祭を、食からゲームへ収益の軸を移して再設計した
  ボランティアのプロジェクト。
○ 食の売上で回っていた学校祭が、COVID で 2 年止まった。戻ったときには
  食も肉も使えない。収益の柱をゲームに移し、3 年かけて 3 倍以上にした。
  ボランティアの持ち回りの役。
```

下は 3 文。状況 → 制約 → やったこと。カタカナは「ボランティア」だけ。

## 4. 英語（EN）側も直す対象

JP を書き直すとき、EN が冗長なら EN も削る。**EN と JP は同じ事実の別表現**であって、
片方が要約であってはならない。長さが 2 倍違ったら、たいてい EN が緩い。

## 6. Claim Guard の修正（この作業で判明した設計の欠陥）

`validate.mjs` の Claim Guard は「Lens が書いた文中の数字が、証拠側に存在するか」を
見る。ここに 2 つ問題がある。

1. **証拠と無関係な数字まで弾く。** CTA の「30 分」は経歴の主張ではない。弾く理由が無い。
2. その結果、**日本語を壊す回避策（「三十分」）を書かせた。** 検査が文章の質を下げている。

修正: `profile.json` に `nonEvidentialFigures`（例: `["30"]`）を置き、Claim Guard は
これを除外する。**証拠の主張だけを守り、日常の数字は通す。**
