# v4 Structured Tech Editorial — デザイン仕様

> Written by: brainstorming + superforge-ui · Last updated: 2026-08-23

## 目的

Takao Umeharaのポートフォリオを、テクノロジーとデザインの両方を設計・実装できる人物として短時間で理解できる、モダンで力強い一枚のインデックスへ再設計する。

訪問者が3秒で専門性とレベルを判断でき、興味を持った作品を同じ空間のまま開き、ブラウザの「戻る」で迷わず元のカードへ戻れることを成功条件とする。

## Surface

- Mode: **Persuade** — 採用担当者や依頼者が「この人と話したい」と判断するための表面。
- Sacrificing: 業務ツールのような高密度表示と、装飾目的の常時アニメーション。
- Scope: **redesign** — 既存の作品内容と事実は保ち、見た目と閲覧構造は置き換える。
- Out of scope: `v3/` の既存ページ変更、CMS化、問い合わせフォーム、作品本文の新規執筆。
- Target: `/Users/takao/Documents/00_Product_Develpment/creativityiseverywhere/v4/` に独立したレビュー用ページを作る。

## Design DNA

Route: **B — existing design**

### Sources

| 参照 | 出所 | 取り入れるもの | 取り入れないもの |
|---|---|---|---|
| Portfolio Minimal | ユーザー提供の `.dc.html` | カードが詳細へ広がる空間遷移、余白、一覧から読書への連続性 | 架空の人物・作品、細いセリフ見出し、低い文字コントラスト |
| v3 portfolio | `../v3/` | 実在する作品、カテゴリ、About、既存画像 | 現行トップページの複雑な演出と複数の視覚言語 |
| ユーザーの指定 | 2026-08-23 | サンセリフ、矩形整列、5カテゴリ、About、LinkedIn、レスポンシブ、アクセシビリティ | 繊細さを優先した細線・細字・低コントラスト |

### Extracted system

- 構造: Header → Hero → Category index → Project grid → About → Contact。詳細は同じページ上の全画面レイヤーで開く。
- 空間: 8px基準。主要な区切りは48〜128px、カード内部は16〜24px。小さな差を多数作らない。
- タイポ: 1.25のMajor Third。`Instrument Sans`を表示・本文へ使用し、`IBM Plex Mono`は年・カテゴリなど短いメタ情報だけに限定する。本文は16px未満にしない。
- 色: 温かいオフホワイトを地、ほぼ黒を本文、強い青を選択・フォーカス・カテゴリ継続線へ限定して使う。色と必ず文字ラベルを併用する。
- モーション: crisp。カード選択と詳細終了の一往復だけを主役にし、常時ループや散発的なスクロールフェードは使わない。
- 画像: 実在するv3のサムネイルを同じ比率でクロップ。カードはすべて4:3、詳細の主要画像は16:9。画像がなくてもレイアウトが崩れない代替面を用意する。

### Deliberate divergence

元のプロトタイプは細いNewsreaderと低い不透明度で静けさを作っていた。v4では静けさを余白と整列で作り、文字は中〜太ウェイト、区切りは見失わない濃度へ上げる。これにより「繊細すぎない」読みやすさと、テック領域での構造的な強さを両立する。

## 検討した3方向

### A. Structured Tech Editorial — 採用

- コンセプト: 技術仕様書の明快さと、デザイン誌の余白を同じグリッドに置く。
- 押す軸: レイアウト。矩形、規則、整列、選択した矩形の拡張を徹底する。
- やらないこと: 装飾的な3D、ガラス表現、常時動く背景、細いセリフ体。
- 費用: 低〜中。CSSと少量のJavaScriptで成立する。
- 向いている相手: Product、AI、Experienceのいずれの担当者にも一つの人物像を伝えたい採用・依頼判断者。

### B. Technical Index — 不採用

一覧性は高いが、Monoと表組みの比重が増え、Brand ExperienceとInteractive Experienceの感情的な価値が弱く見えるため。

### C. Visual Gallery — 不採用

第一印象は強いが、画像品質・通信量への依存が高く、AI ToolsとProduct Designの設計能力が説明不足になりやすいため。

## 情報設計

### Header

- 左: `Takao Umehara`。トップへ戻るリンク。
- 中: 5カテゴリのアンカー。デスクトップでは常時表示する。
- 右: `About` と外部リンクの `LinkedIn ↗`。
- モバイル: 名前とMenuボタン。Menuはネイティブボタンで開き、5カテゴリ、About、LinkedInを44px以上の行として表示する。

### Hero

- 一つの見出しで、Interactive Experience、AI Products、design systemsを横断して設計・実装する人物であることを示す。
- 補足文は2行以内。職歴年数や成果数値など、既存資料で裏付けられない新規主張は書かない。
- 主な行動はプロジェクトを見ること。別のCTAボタンは増やさない。

### Category index

- `Interactive Experience / AI Products / AI Tools / Product Design / Brand Experience`を同じ階層で表示する。
- 各カテゴリはページ内セクションへ移動し、選択中は太い下線と`aria-current`で示す。
- カテゴリの意味は色だけに依存させない。

### Project grid

- 実在するv3の代表作品を各カテゴリから選び、架空のタイトル・クライアント・成果を作らない。
- デスクトップは12列グリッド上の2〜3列、タブレットは2列、モバイルは1列。
- 同じ行のカードは同じ高さ。画像4:3、タイトル、カテゴリ、年、1〜2行の説明を固定順で置く。
- カード全体を一つのネイティブボタンとして操作可能にする。内部へ別リンクを入れ子にしない。

### Project detail

- ネイティブ`<dialog>`を全画面で使い、タイトル、カテゴリ、年、役割、要約、主要画像、既存ケーススタディへのリンクを表示する。
- 選択したカードの矩形から画面全体へ`transform`と`opacity`のみで拡大する。
- 同じカテゴリの短いアクセント線をカードと詳細に残し、空間的な連続性を補強する。カテゴリ文字も常に併記する。
- 閉じる、前へ、次へを用意する。閉じるボタンには`Close project`のアクセシブルネームを持たせる。

### About / Contact

- v3のAboutにある事実だけを使い、現在の専門領域と仕事の進め方を2段落以内でまとめる。
- LinkedInはHeaderと最下部の両方に置く。
- URLは `https://linkedin.com/in/takaoumehara` とし、新規タブで開くことを視覚・読み上げの両方で示す。

## 遷移と履歴

1. カード選択時にスクロール位置、トリガー要素、カード矩形を保存する。
2. `history.pushState`でプロジェクトslugをURLへ追加する。
3. dialogを開き、保存した矩形から全画面へ展開する。
4. ブラウザの「戻る」またはEscで履歴を戻し、dialogを閉じる。
5. 保存したスクロール位置とトリガーのフォーカスを復帰する。
6. URLを直接開いた場合は該当プロジェクトを即時表示し、閉じた際はカテゴリ位置へ戻す。

`prefers-reduced-motion: reduce`では拡大・縮小を行わず、表示を即時切り替える。View Transition APIは補助的な強化として扱い、非対応ブラウザでも機能を失わない。

## コンポーネント境界

- `SiteHeader`: ナビゲーション、モバイルメニュー、現在カテゴリ。
- `Hero`: ページの主張と補足。
- `CategorySection`: 見出しとプロジェクトグリッド。
- `ProjectCard`: 画像、メタ情報、開く操作。
- `ProjectDialog`: 詳細表示、履歴、前後移動、フォーカス管理。
- `AboutSection`: 短いプロフィールとLinkedIn。
- `ProjectRegistry`: v3から確認済みの作品情報だけを保持するデータ配列。

実装は単一HTMLでも、この境界がCSSの命名とJavaScript関数に表れるようにする。`support.js`は生成物のためコピー・編集せず、ブラウザ標準APIで実装する。

## エラーとフォールバック

- 画像の読み込み失敗: カテゴリ名と作品名を含む高コントラストの代替面へ切り替える。
- 不明なproject slug: dialogを開かずURLを正規化し、ページ上部へ短いステータスを通知する。
- JavaScript無効: 全カードは既存のv3ケーススタディへ通常リンクとして移動できる。
- dialogまたはアニメーションAPI非対応: 通常リンクまたは即時表示へフォールバックする。
- フォント取得失敗: `ui-sans-serif, system-ui, sans-serif`で同じ行長を保つ。

## アクセシビリティ要件

- 目標: WCAG 2.2 AA、Web、ページ全体とカード→詳細→戻るの完全なフロー。
- `header/nav/main/section/footer/dialog`を意味どおりに使い、見出し順を飛ばさない。
- Skip link、明確な3px以上の`:focus-visible`、44px以上の主要操作領域を設ける。
- 本文16px以上、line-height 1.5以上、英語本文45〜75文字幅。
- 通常文字4.5:1以上、大文字3:1以上、UI境界3:1以上を実測する。
- dialog表示中は背面を操作できない。Esc、閉じるボタン、ブラウザの戻るを同じ結果へ結ぶ。
- 320 CSS px、200%テキスト拡大、400%ズームで横スクロールと機能欠落を起こさない。
- 画像altは作品の内容を説明し、隣接文と重複する場合は装飾画像として空altにする。
- 新規タブ、外部リンク、選択中カテゴリを色だけで示さない。

## パフォーマンス予算

- 1画面目で理解可能になるまで: ローカル環境で1秒以内を目標。
- 操作への視覚応答: 100ms以内。
- 初期HTML/CSS/JS: 合計150KB以内。画像は最初の表示範囲を除いて`loading="lazy"`。
- JavaScriptフレームワーク、3D、常時稼働する描画ループは使用しない。

## 検証

### 自動

- HTML構造、リンク切れ、重複ID、必須カテゴリ、LinkedIn URL、画像パスを検査するNodeテスト。
- 利用可能ならPlaywright + axeで自動検査する。ただし自動検査だけで適合を宣言しない。

### 手動・実行

1. 自動検査
2. キーボードのみで全カテゴリ、カード、詳細、戻るを操作
3. VoiceOverで名前・役割・順序を確認
4. 320px、200%テキスト、400%ズームでリフロー確認
5. 色とコントラストを計算
6. reduced motionで即時遷移を確認
7. フォームは存在しないためNot presentとして記録

結果は`docs/accessibility.md`へ、デザイントークンとコンポーネント見本は`docs/design.md`と`docs/design.html`へ同じターンで保存する。

## 受け入れ条件

- `v4/`だけでレビュー用ページを開け、`v3/`のファイルに差分がない。
- 5カテゴリ、About、指定LinkedInが表示される。
- デスクトップ、タブレット、320pxモバイルで矩形カードが崩れない。
- カードを開き、ブラウザの戻るで元のスクロール位置とカードフォーカスへ復帰する。
- マウス、タッチ、キーボード、Escの各入力で同じ主要フローを完了できる。
- reduced motionで意味や操作を失わない。
- 架空の人物名、作品名、クライアント名、成果数値を含まない。
- 7パスの実行結果と、実行できなかった項目が区別して記録される。
