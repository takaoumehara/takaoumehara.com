# プロジェクト詳細ページ ヒアリング指示書 v4（各プロジェクトのAIセッションに貼る用）

Updated: 2026-09-27 — **v4**。`docs/portfolio-content-intake-prompt.md`（v3）の後継。

## v3 から何が変わったか

v3 は「1枚1メッセージのスライド」（Hero → Tension → Approach → … → Closing、9〜14枚）を
埋めさせる設計だった。ページはその後 **ロック済みの詳細フォーマット**（2026-09-25、
`docs/project-page-format.md` 冒頭）に変わったので、v3 の出力はもう 1:1 で流し込めない。

現行のページは、上から次の順で**これだけ**:

```
teaser（16:9）  ← 実物のミュートループ動画 / 静止画 / 動く試作の埋め込み。無ければ名前の文字組
h1              ← 案件名だけ（コロン以下のタグラインは付けない）
one-liner       ← それが「何か」（EN + JP）
Play            ← 遊べる公開URLがある時だけ。ページで唯一の外部リンク
Challenge | Solution ← 状況の摩擦 ｜ 決定打ひとつ
body            ← 0〜3 ビート（見出し＋本文＋画像/動画＋任意で数字3つまで）
Role / Year / Client、Stack（フッター1行）
```

v4 はこの型の**スロットと 1:1 対応**する項目だけを聞く。スライドの枚数を埋めるための
質問（Tension の前後、Structure、Retrospective、Closing、アクセント色）は全部やめた。
代わりに**素材（画像・動画）の提案と撮影指示**を厚くした。ページの主役が文章から
teaser とビートの画像に移ったため。

実装側のファイル:
- 値の解決: `src/lib/detail.mjs` / 描画: `src/components/project/ProjectDetail.astro`
- テキストと素材パス: `src/data/{projects,experiments,tools,ventures}/<slug>.json`（`detail` ブロック）
- ビート本文: `src/case-studies/<slug>.html`（`<section class="beat">` を 0〜3 個）
- 検査: `tests/detail-format.test.mjs`

## 使い方（自分用）

1. 下の「対象プロジェクトと現状」表から、そのプロジェクトの行を探す。
2. 「貼り付け用プロンプト」をコピーし、冒頭の `【このページの現状】` の 3 行だけ、
   表の内容で書き換える（スラッグ・現在のURL・薄いところ）。
3. そのプロジェクトのリポジトリを開いている AI セッションに貼る。
4. 返ってきた Markdown（`portfolio-detail-<slug>.md`）を、このリポジトリのセッションに
   そのまま貼る。素材ファイルは、相手が `portfolio-handoff/<slug>/` に置いて push した
   リポジトリ名を一緒に伝える（こちらで取りに行ける）。
5. 先に `## 9. 本人への質問` だけ答えておくと、1 往復で実装まで進む。
6. `## 7. 撮影リスト` の ③（本人が撮る）が今回の宿題。撮れたものから順に渡せばよい。
   全部揃うのを待つ必要はない — 文章だけ先に入れ、素材は後から差し替えられる。

## 7. 撮影リスト（③ と、動画が足りない分）

**動画が無い、または今ある動画が古い・重い・使えない場合は、撮り直し前提で
撮影リストを書いてください。** 本人はこのリストだけ見て撮影を始めます。

先頭に「本人の TODO」として ③ の一覧と所要時間の合計を置き、その後に各素材の
撮影指示を次の形で書く:

```
【撮影指示】M2 teaser ループ
- 目的        : teaser / ビート N（どこに使うか）
- 何を写すか  : 画面のどの状態から、どの操作で、どの状態まで。1〜3 行
- 見せたい瞬間: この動画で一番伝えたい 1 秒（例: 声を出した瞬間に文字が弾ける）
- 使う道具    : Mac の画面収録（⌘⇧5）/ QuickTime / OBS / iPhone の画面収録 /
               iPhone ＋ 三脚 など、本人が持っていそうなもの。不明なら §9 で聞く
- 準備        : ウィンドウサイズ、テストデータ、通知オフ、カーソル表示の有無 など
- 手順        : 番号付き 5 ステップ以内
- 出力        : 比率・寸法・fps・尺・音の有無・ファイル名
- 失敗しやすい点: これを外すと撮り直し、という点を 1 行
- 所要時間    : 5 分 / 30 分 / 半日
```

### 動画の出力仕様（迷ったらこれ）

- **teaser ループ（ページ最上部で自動再生）**
  - 16:9、**1920×1080 で収録**（ポートフォリオ側で 1280×720 の webm＋mp4 に書き出す）
  - 30fps、**6〜12 秒**、**音無しで成立すること**（自動再生はミュート固定）
  - 最初と最後のフレームが近い状態で終わる（ループの継ぎ目が目立たない）
  - 冒頭 1 秒で「何か」が分かる。ロゴやタイトルカードから始めない
  - 文字が小さい UI は、ブラウザの拡大率を 125〜150% にして撮る
  - PC ブラウザで撮るなら: ウィンドウの中身をちょうど 1920×1080 にする
    （Chrome の DevTools のデバイスツールバーで 1920×1080 を指定し、その領域だけ
    ⌘⇧5 の「選択部分を収録」で撮る）。タブやアドレスバーは写さない
- **スマホで操作する作品**
  - スマホ画面は iPhone の画面収録（縦 9:16。そのままの解像度で可）
  - teaser は 16:9 なので、縦の画面 1 本だけでは枠が埋まらない。次のどちらかにする:
    (a) 大画面側（PC・プロジェクター）を 16:9 で撮り、スマホは右下に小窓で合成
    (b) スマホを持った手と大画面が同時に写るよう、三脚のカメラで 16:9 の実写
- **スマホ → 大画面が反応する作品（複数端末）**
  - 2 本を同時再生して同期させようとしない。**編集で 1 本に合成する**
    （ページ上の 2 つのプレイヤーは同期しない）
  - 両方の録画を回し始めたら、**両方に同時に映る一瞬の合図**を最初に入れる
    （スマホを 1 回タップして大画面に特徴的な反応が出る瞬間、など）。編集ではそこで頭を揃える
  - 大画面を主、スマホを小窓。書き出しは 16:9・1920×1080・20〜40 秒・1 ファイル
  - 「その場の人が反応している」ことが主張なら、画面収録より実写（三脚）が強い
- **比較（旧版と新版）** は同期させず、2 本を別々に並べる（見る人が自分のペースで見比べる）
- **ビート用の説明動画** は 20〜40 秒。長いと最後まで見られない。
  音声解説が要る作品は、その旨を書く（その場合のみ音ありで収録）
- **声・音が主役の作品**（声で操作する等）: 画面収録に**マイク音声を入れて**撮る
  （teaser は無音再生だが、ビートで音あり動画として使う）。
  iPhone の画面収録はコントロールセンターで長押し → マイクをオンにする
- **顔・身体が入力の作品**: 本人が映ってよいかを §9 で確認する。
  顔を出さない場合は、カメラ映像を切って、画面側の反応だけを撮る案も書く
