# ページ遷移 — サムネイルが詳細ページのヒーローになる

> Written by: superforge-ui · 2026-09-12 · 対象: `claude/stoic-pasteur-zhusuy`（PR #15）

カードを押したときに画面が切り替わるのではなく、**押したサムネイルがそのまま
詳細ページのヒーロー帯へ育つ**。周りは薄く消えて、新しいページがわずかに
せり上がって落ち着く。

使っているのは Cross-document View Transitions（CSS の `@view-transition` と
`pageswap` / `pagereveal`）。JavaScript でページを差し替えるのではなく、通常の
遷移のまま、ブラウザに前後 2 枚のスナップショットを繋いでもらう。対応していない
ブラウザ（現時点では Firefox）は、これまでどおりただ遷移する。**壊れる余地が
どこにもないことが、この方式を選んだ理由**で、ここにあるものは一つも
load-bearing ではない。

## 半分ずつ、両方ないと動かない

| | どこ | 何をしているか |
|---|---|---|
| 出す側（一覧） | `src/render/lens.css` + `src/render/shell.mjs` | 押されたカードの画像枠に `view-transition-name: hero-media` を付ける |
| 受ける側（詳細） | 各 HTML の `<head>` 内 `<style>` | ヒーロー要素の `data-vt-hero` に同じ名前を付ける |

どちらか片方だけでは**何も起きない**。そして何も起きないことがエラーとして
表に出ない。だから `tests/page-transitions.test.mjs` が両側の存在を検査する。

## 名前は一度に一つしか置けない

`view-transition-name` は 1 つの文書の中で一意でなければならない。**二つの要素に
同じ名前が付くと、ブラウザはどちらかを選ぶのではなく遷移そのものを捨てる。**

これは実際に起きていた。以前の受け側の規則は

```css
.project-hero, .wds-hero { view-transition-name: hero-media; }
```

で、`projects/verizon-ai-agents.html` ではこれに **9 個**の要素が一致していた。
つまりあのページだけ、書いてあるのに一度も動いていなかった。クラス名は他の用途に
再利用されるので、そこに一意性を期待してはいけない。いまは各ページで
**ちょうど 1 つの要素**に付けた `data-vt-hero` を見る。テストがこの数を数えている。

同じ理由で、一覧側はカード全部に名前を配らない。`shell.mjs` は `pageswap` の
中で**行き先の URL に一致するカード 1 枚だけ**に名前を付け、遷移が終わったら
外す。クリックハンドラではなく `pageswap` を使っているのは、カード本体・中の
「ケーススタディ →」リンク・戻るボタンのすべてを 1 か所で拾えるから。

## 3:2 のサムネイルと全面ヒーローは形が違う

`::view-transition-old/new` の既定は `object-fit: fill` で、縦横比の違う 2 枚を
繋ぐと移動中に画が潰れる。`object-fit: cover` に変えて、潰さず切り取る。これが
「2 枚の絵が入れ替わった」ではなく「1 つの要素が動いた」に見えるかどうかの分かれ目。

## 動きを減らす設定

一覧側は `prefers-reduced-motion: reduce` のとき**そもそも名前を付けない**ので、
モーフは起きない。受け側も `view-transition-name: none` で明示的に切る。残るのは
1ms のクロスフェード、つまり実質的に即時の遷移。

## 確認したこと

Chromium 141 で実際に遷移させ、以下を確認した。

- `pageswap` 時に名前が付いているのは 1 要素だけ（`cat-card-media=hero-media`）
- 受け側で `pagereveal` の `viewTransition` が有効、`[data-vt-hero]` は 1 個
- 遷移を 4 秒に引き伸ばした中間フレームで、カードの画像がヒーロー帯へ育っている
- `npm test` 55 / `npm run test:e2e` 26、いずれも通過

> この環境は Google Fonts と jsdelivr に出られない。レンダリングを止める
> `<link rel="stylesheet">` が応答しないと**最初の描画が遅れ、その分だけ
> ブラウザは遷移への参加を諦める**。検証ではそれらのリクエストを即失敗させて
> 本番と同じ条件に近づけた。実サイトでは問題にならないが、フォントの読み込みが
> 極端に遅い回線では遷移が省略されることがある（省略されても遷移自体は成功する）。

## ページを足すとき

詳細ページを新しく作ったら、`<head>` の `<style>` に既存ページと同じブロックを
入れて、ヒーロー要素に `data-vt-hero` を 1 つだけ付ける。忘れると
`tests/page-transitions.test.mjs` が名指しで落とす。
