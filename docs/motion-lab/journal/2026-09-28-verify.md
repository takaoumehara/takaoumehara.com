## 見つけた問題
1. **aria-busy の一瞬の解除**（何が）：`replay("nav")` の OUT→IN の切り替わりで、`#main` の `aria-busy` が
   一瞬 `null` に戻り、空の `.mo-layer` が残る窓（観測ではおよそ 150–300ms）がある（どこ）：
   `src/scripts/motion.js` の `paneOut()`（977–1021行）は `busy()` を呼ばない。`busy()` は `run()`/`execute()`
   内でのみ呼ばれる。（再現）：`/lab/stage` で「Page change」をクリックし、40ms間隔で
   `document.getElementById("main").getAttribute("aria-busy")` をポーリング。（確度）高（2回の独立トレースで
   再現）。（重さ）低——最終的には契約どおり settle し、`.mo-layer` も消えるが、ファイル冒頭のコメント
   「`#main`（と rail 再生中は `#side`）は `aria-busy="true"` を持つ」という不変条件には一瞬反する。
   Motion Lab 固有の新規コードではなく既存 v1 エンジンの挙動。
2. **既存 e2e：Werewolf の色コントラスト**（何が）：`color-contrast (serious)` — `a[href$="typespace.html"]
   > .side-text > .side-line > .t-en` と `.project-oneliner > .t-en`（どこ）：`tests/a11y.spec.mjs:37`
   （再現）：`npm run test:e2e` の該当ケース。（確度）高。（重さ）中——必須テストを落とすが、今回の
   Motion Lab のコミット（`git log` で `src/pages`,`src/components` への変更なし）とは無関係の既存不具合。
3. **既存 e2e：ホーム `/` に `[data-href]` が 0 件**（何が）：`page.locator("[data-href]").count()` が 0 →
   キーボードで開けるカードが無いと判定される（どこ）：`tests/a11y.spec.mjs:51-61`。実HTML でも確認
   （`curl http://127.0.0.1:4320/` に `data-href="` が0件、`/work.html` は44件）。原因候補：
   `src/components/grid/GridCard.astro:31` の `data-href={to ? to.url : undefined}` が home では `to` 未設定。
   （再現）：`curl -s $BASE/ | grep -c 'data-href="'` → 0。（確度）高。（重さ）中——同じく Motion Lab の
   変更ファイルではない（`git log` 上、今日のコミットは `src/pages/index.astro` 等に触れていない）。
4. **h の1件は非問題**：401 route に対する Chromium 自身の resource-error コンソールログを
   「console error」として拾っただけ。アプリの表示・挙動は正しい（上記参照）。（確度）高。（重さ）— 該当なし。
5. **環境上の制約**：Clerk 未設定のためサンドボックスでは `/api/admin/*` が実際には 401 ではなく 503 を返す。
   これは検証環境の制約であり Motion Lab のコードの欠陥ではない（`src/pages/api/admin/_auth.ts` の
   `denyUnlessAdmin()` の設計どおり）。（確度）高。（重さ）情報のみ。
