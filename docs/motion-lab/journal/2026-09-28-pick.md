# 2026-09-28 — 「残すか捨てるか」ピッカー（motion-pick.js）

- **目的**: 116 本のスライダーの代わりに、候補の読み込みを 1 つ見て Keep / Toss を押す。8 回で候補リスト（shortlist）ができ、そこから試す・適用・JSON コピー。
- **api（ページ側が渡す）**: `mountPick(root, api)` → `{ destroy() }`。`api.candidates(n)` は有効な v2 config の候補 `[{ name, config }]`、`api.play(config)` はステージで再生、`api.apply(config)` はツールの現在の選択（パネルの作業コピー）にする、`api.copy(text)` は Promise。apply には `structuredClone` した config を渡す（保存中のものを書き換えられないように）。
- **ファイル**: DOM は `src/scripts/motion-pick.js`（CSS `src/styles/motion-pick.css` を import）。純粋な部分は `src/scripts/motion-pick-core.mjs`（Node で直接テスト）。motion-pick.js は `readKept` / `writeKept` / `nextRound` を再 export。
- **状態機械 `nextRound(state, verdict)`**: state = `{ phase: "intro" | "round" | "list", round, queue, kept }`。`start` で queue の 0 番目から（queue が空なら即 list）。`keep` は現在の候補を kept に追加（name で重複排除、既存が優先）して次へ、`toss` は次へ、`finish` は即 list。`min(8, queue.length)` 回終えると list。合わない verdict は state をそのまま返す。
- **保存**: `localStorage["tu-motion-kept"]` = `{ v: 1, kept: [{ name, config, at }] }`。読み書きとも try/catch。壊れた値・v≠1 は空扱い、不正な行は 1 行ずつ捨てる。起動時に kept があれば shortlist から始まる（リロードで残る）。
- **キー**: K / → = Keep、J / ← = Toss。round 表示中だけ、フォーカスがピッカー内か body のときだけ。input / textarea / select / contenteditable、修飾キー、キーリピートでは発火しない。`destroy()` で keydown を外し root を空にする。
- **見た目**: `var(--pr-card)` のカード、8px 角丸、13px、ウェイト 400 のみ、mono 大文字 10px ラベル。青はフォーカスリングと「適用中」の行名だけ。Keep/Toss は 44px 以上（実測 51px）、coarse pointer では全ボタン 44px。英日は `.t-en` / `.t-jp`（ホスト側に規則が無くても効くよう CSS にも同じ規則）。
- **確認**: `node --test tests/motion-pick.test.mjs` 9/9。ブラウザは偽 api のハーネス（dev サーバーに route で同一オリジン配信）で Start→K→J→Keep×3→Finish early→Use/Try/Copy→リロード→×→Another 8→外部 input のキー無効→Clear→壊れた保存値→destroy まで、コンソールエラー 0。
